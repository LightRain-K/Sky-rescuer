# Борт: демо на Raspberry Pi 3 + SpeedyBee F405

Задача: через две недели **показать**, что комплекс работает — картинка
обрабатывается, объект находится, моторы реагируют. Летать не обязательно:
демонстрация идёт на столе, с снятыми пропеллерами.

---

## Что реально влезает в Pi 3

Замеры на ноутбужном CPU (4 потока, NCNN, среднее по 30–40 кадрам):

| Модель | Вход | мс/кадр | fps |
|---|---|---|---|
| вода (YOLO11n) | 320 | 14.6 | 68.6 |
| вода (YOLO11n) | 640 | 50.0 | 20.0 |
| вода (YOLO11n) | 960 | 110 | 9.1 |
| огонь (YOLO11s) | 320 | 27.0 | 37.0 |
| огонь (YOLO11s) | 960 | 254 | 3.9 |

Pi 3 — это Cortex-A53 1.2 ГГц и 1 ГБ памяти, примерно в 6–10 раз медленнее
десктопа. Ожидаемо:

- **вода @320: 100–250 мс → 4–10 fps** — годится для демо;
- **огонь @320: 150–350 мс → 3–6 fps** — годится, но с запасом на перегрев;
- **960 на Pi 3 не трогаем** — будет 1–2 с на кадр.

Поэтому для борта экспортируем модели в 320 (папки `*_ncnn_model` уже собраны):
`runs/sea_yolo11n_960/weights/best320_ncnn_model`,
`runs/mixed_v3_final/weights/best320_ncnn_model`.

Для соревновательного показа лучше гнать **видеофайл**, а не живую камеру:
нет проблем с драйверами, стабильный fps и повторяемость.

## Что показываем (сценарий 3 минуты)

1. На столе — рама с F405, пропеллеры **сняты**, питание от БП/АКБ.
2. Pi 3 подключён к F405 по UART, к Pi — HDMI-монитор.
3. Запускается обработка видео: на экране рамки, подписи класса и уверенности.
4. Когда модель уверенно находит объект 3 кадра из 5 — на экране «ALARM»,
   и моторы по очереди дёргаются (визуальная реакция борта).
5. Второй прогон — на кадре без объекта: тишина, моторы стоят.

Это ровно то, что просят: «моторы поменяли положение, картинка обработалась».

## Подключение Pi ↔ F405

| Pi (40-pin) | F405 | Примечание |
|---|---|---|
| GPIO14 / pin 8 (TXD) | RX любого свободного UART | данные Pi → плата |
| GPIO15 / pin 10 (RXD) | TX того же UART | данные плата → Pi |
| GND / pin 6 | GND | обязательно общий |
| 5V / pin 2 — **не подключать** | — | питать Pi отдельно, от своего BEC |

- Скорость: **115200**.
- В Betaflight: вкладка **Ports** → на выбранном UART включить **MSP**, 115200.
- На Pi: `sudo raspi-config` → Interface Options → Serial Port →
  «login shell over serial» = **No**, «serial hardware enabled» = **Yes**.
  После перезагрузки порт — `/dev/serial0` (или `/dev/ttyAMA0`).
- Проверка связи: `python onboard/motor_demo.py --port /dev/serial0 --probe`
  должно вернуть версию MSP API.

## Установка на Pi 3

```
sudo apt update && sudo apt install -y python3-venv python3-pip libopenblas-dev
python3 -m venv ~/venv && source ~/venv/bin/activate
pip install --upgrade pip
pip install torch --index-url https://download.pytorch.org/whl/cpu   # ARM64, CPU
pip install ultralytics ncnn pyserial opencv-python-headless
```

Если памяти не хватает (1 ГБ): увеличить swap до 1–2 ГБ
(`sudo dphys-swapfile setup` / `swapon`), закрыть лишнее, использовать
модель 320 и `--imgsz 320`.

Копируем на Pi: папку `*_ncnn_model`, скрипты `onboard/*.py`, тестовое видео.

## Запуск

Сухой прогон (без платы) — проверить логику:

```
python onboard/pipeline.py --profile water --source demo.mp4 \
    --weights best320_ncnn_model --imgsz 320 --no-display
```

Реальный прогон с реакцией моторов (два процесса или два окна):

```
# окно 1: зрение пишет тревоги в runs/onboard/...
python onboard/pipeline.py --profile water --source demo.mp4 \
    --weights best320_ncnn_model --imgsz 320 --no-display

# окно 2: моторы слушают файл тревог и дёргаются
python onboard/motor_demo.py --port /dev/serial0 --sequence alarms \
    --alarm-file runs/onboard/<последняя папка>/alarms.jsonl --arm
```

Проверка моторов без зрения:

```
python onboard/motor_demo.py --port /dev/serial0 --sequence motors --arm
```

## Безопасность

- **Пропеллеры снять.** Всегда, при любом тесте моторов на столе.
- Рама закреплена, питание через предохранитель/БП с ограничением тока.
- `--arm` включает реальную отправку команд; без него — сухой прогон.
- При выходе скрипт всегда отправляет «стоп» (1000 на все каналы).
- Если плата игнорирует `MSP_SET_MOTOR`: проверить, что в Betaflight
  выбран протокол моторов (DSHOT), плата **не вarmed**, и прошивка
  поддерживает мотор-тест по MSP (в конфигураторе вкладка Motors работает).

## Что говорить на показе

«Борт обрабатывает видео локально, без интернета. Модель нашла объект в
3 кадрах из 5 — сработала тревога, и плата получила команду: моторы
отработали. Это тот же код, что пойдёт на самолёт; на Pi 5 он работает
в 3–5 раз быстрее, здесь мы сознательно взяли самый слабый компьютер,
чтобы показать, что система не требует мощного железа».

Чего не обещать: автономного полёта, точности «до метра» и определения
«тонет человек или плывёт». Это следующие этапы.
